# 网络自费售药来源审查

描述网络自费售药场景中的来源审查和处置边界。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 回流药转向互联网和自费渠道销售
- 正规来源与风险来源需要区分
- 处置范围应对应实际购买批次
- 低价或异地发货本身不构成违规
- 下架决定必须说明具体证据
- 未解决问题前不得换链接重新上架
- 买家告知只覆盖受影响批次

## 来源审查案例资料

`contracts/source-review.schema.json` 描述售药来源审查后台所需的案例资料格式，`fixtures/review-case.json` 给出一个虚构的完整案例：

- **在售版本备案**：商家为每个在售版本提交经营资质、采购批次（含追溯码范围与票据摘要）、实际发货主体和温控承诺。
- **订单履约快照**：履约时固定买家看到的页面与所用批次、实际发货主体和收发区域。
- **风险信号**：追溯码重复、来源证明过期、商品替换、异地代发为强信号；低价、异地发货只是弱信号。
- **分级处置**：观察、限流、下架三级，附证据清单、受影响订单范围和恢复条件。
- **留痕记录**：商家申诉、平台复核、监管通知、买家风险告知各自留痕。

## 处置边界

`src/review.js` 在整案校验中强制以下边界：

- 低价或异地发货等弱信号只能观察，不得升级为限流或下架，避免误伤正规药房。
- 下架决定必须说明具体证据，证据需指向可追溯的记录。
- 处置的订单范围必须对应受影响批次的实际订单。
- 买家告知只覆盖受影响批次的订单，无关买家不受打扰。
- 存在未解决处置时，同一商家同一药品不得换链接重新上架。
- 普通审核员只能查看未解决处置范围内的买家订单；管理者可以从一次处置追到相关商品版本、订单范围和恢复条件。

## 本地校验

运行 `npm test` 即可确认样例资料可读取、领域标识与版本字段完整，且案例资料满足全部处置边界。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。
