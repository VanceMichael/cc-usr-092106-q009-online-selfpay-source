# 网络自费售药来源审查

描述网络自费售药场景中的来源审查和处置边界。

## 领域资料

合同（`contracts/`）与示例（`fixtures/`）成对出现，代码库只负责读取与按领域规则校验这些资料，业务服务可沿用相同标识和版本约定：

| 合同 | 示例 | 内容 |
| --- | --- | --- |
| `context.schema.json` | `context.json` | 领域标识、版本与事实清单 |
| `source-filing.schema.json` | `source-filing.json` | 商家按在售版本提交的经营资质、采购批次、追溯码范围、票据摘要、实际发货主体、温控承诺与备案页面快照 |
| `fulfillment-ledger.schema.json` | `fulfillment-ledger.json` | 订单履约时固定的买家所见页面版本、锁定批次、实际发货主体/仓与追溯码；低价、异地仅作观察项 |
| `review-case.schema.json` | `review-case.json` | 信号、证据、分级处置、申诉、复核、监管通知、买家告知、重新上架尝试、未解决问题、恢复条件与访问留痕 |

## 规则要点

- 自费慢病药按**在售版本**报备；履约时锁定买家看到的页面哈希与采购批次，事后页面替换可比对发现。
- 风险信号：追溯码跨订单重复、追溯码不属于锁定批次码段（区分错批次与无归属）、来源证明（资质）过期、页面/版本替换、未报备主体或地址发货、温控失约。
- **低价、异地发货不单独构成风险**：示例订单 O-1002 价格更低且由已报备的跨省授权仓发货，校验结果为无信号；只有未报备主体（O-1006 的 E-99）才判定异地代发。
- 处置分三级：1 关注观察、2 限制（暂停新订单）、3 下架。下架必须引用带来源与采集时间的具体证据并写明理由，无证据的下架决定会被校验拒绝。
- 买家告知按批次精确投放：只能发给实际购买所通知批次的订单，禁止扩大到无关买家。
- 旧链接重新上架时，生效中的下架处置、未解决问题（open）或未满足的恢复条件会强制阻断并留痕；复核推翻的处置不再阻断。
- 权限最小化：案卷中只出现买家假名（buyer_ref）；普通审核员只能查看生效处置范围内订单对应的买家，越界访问与案卷范围外访问一律判为违规；复核须由上级角色完成。
- `buildCaseTrace` 从一次处置向下追溯到商品版本、批次、订单范围、证据、申诉复核结论与恢复条件，支撑管理者闭环核查。

测试覆盖：正规低价/异地订单不被误伤、重复码与越界码识别、页面替换、未报备代发、无证据下架被拒、告知范围精确性、重新上架阻断、访问权限拒绝，以及处置追溯链完整性。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。
